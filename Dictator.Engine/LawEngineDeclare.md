# Спецификация ядра «Язык законов»

*Версия 0.1. Сводка решений по итогам обсуждения. Платформа: .NET Standard 2.1. Код не написан.*

Пометки в тексте: **\[Принято\]** есть явное решение автора игры. **\[По умолчанию\]** предложение, возражений не прозвучало, но явного подтверждения нет. **\[Открыто\]** не решено, ничего не придумано.

## 1. Назначение и контекст

Игра: градостроительный симулятор диктатора в реальном времени с управлением скоростью (пауза, нормальная, ускорение). Игрок выиграл демократические выборы и должен закрепиться у власти. Главная механика: игрок издаёт законы (конституция, кодексы, указы), а горожане и государство живут по ним.

Этот документ описывает только **ядро права**: язык законов, его AST, интерпретатор, определения, акты и реестр. Симуляция города, здания, ИИ агентов и графика сюда не входят.

Технические рамки:

- Библиотека .NET Standard 2.1, не привязанная к игровому движку.
- Классический ООП.
- Данные и законы сериализуются в JSON.
- Расширяемость через моды (подробности в разделе 6).
- Парсера текста в ядре нет: дерево закона строит редактор (блоки в духе Scratch). Позже возможен отдельный слой, превращающий «контролируемый естественный язык» в то же дерево, ядро о нём не знает.

## 2. Принципы

1. **Закон это чистая функция.** Вход: типизированные аргументы. Тело: AST с зашитыми константами и определениями. Выход: результат вычисления. Закон не читает и не меняет мир. **\[Принято\]**
2. **Законы нормативны.** Закон ничего не исполняет, а сообщает, что разрешено, запрещено или обязательно и какие последствия предусмотрены. Что с этим делать, решает агент: следовать, игнорировать, не признавать власть, действовать из собственных мотивов. **\[Принято\]**
3. **Закон выполняется только по запросу.** Нет расписания и нет понятия «закон действует сейчас». Запускает вычисление тот, кому оно нужно (полицейский на задании, бдительный гражданин, судья). Стоимость вычисления относится к тому, кто спросил. **\[Принято\]**
4. **Данные собирает наблюдатель, а не закон.** Мир измеряет и передаёт факты, закон их не проверяет. Поэтому наблюдатель может ошибаться, подделывать данные и коррумпироваться, и закон применится к подделке добросовестно. Это намеренная игровая механика. **\[Принято\]**
5. **Закон ничего не знает о мире, мир знает о законе.** Мир знает только сигнатуры (какие аргументы требует норма) и берёт из законов понятия (органы, статусы, термины), из которых строит свои сущности. **\[Принято\]**
6. **Интерпретатор детерминирован.** Одинаковые аргументы всегда дают одинаковый результат. Никаких часов, случайностей и обращений к миру внутри вычисления. **\[Принято\]**
7. **Язык Тьюринг-полный** (условия, циклы, рекурсия), ограничение накладывается счётчиком шагов (gas). Позже язык можно урезать. **\[Принято\]**
8. **Всё является выражением.** У каждого узла есть тип результата. **\[Принято\]**
9. **Типы проверяются при сборке закона**, а не во время выполнения. **\[Принято\]**
10. **Набор видов узлов фиксирован.** Расширяются только типы данных, их операции и встроенные чистые функции. **\[Принято\]**
11. **Локальные переменные изменяемы**, но живут только внутри одного вызова. Мир закон изменить не может. **\[Принято\]**
12. **Ошибки это данные, а не исключения.** Сообщение должно быть понятным игроку и указывать место в законе. **\[Принято\]**
13. **Поиск применимой нормы и разрешение коллизий принадлежат миру**, в том числе коллизии внутри одного акта и между актами. Иерархия актов в части приоритета это условность, которую соблюдает (или нарушает) мир. Это даёт рычаги коррупции и произвола. **\[Принято\]**
14. **Видимость определений между актами проверяет ядро** (раздел 10). **\[Принято\]**

## 3. Границы ответственности

| Область | Ядро права | Мир |
| --- | --- | --- |
| Язык, AST, типы | Определяет | Использует готовое |
| Интерпретатор, gas | Выполняет | Вызывает и платит gas |
| Определения, акты, реестр определений | Хранит, проверяет ссылки и видимость | Читает, порождает из них свои сущности |
| Поиск нормы по ситуации | Нет | Да |
| Выбор между нормами, коллизии, приоритет актов | Нет | Да |
| Сбор данных для вызова (снимок субъекта) | Только формат снимка | Собирает, может подделывать |
| Реестры статусов | Только формат записи | Хранит у организаций |
| Наблюдение состояний | Только тип | Измеряет |
| Исполнение санкций | Нет | Да |
| Решение агента следовать закону | Нет | Да |
| Результат «закон молчит» | Только тип в общем словаре | Производит сам |

Граница зависит от одного общего контракта: сигнатура нормы описывает, что наблюдатель обязан собрать и передать.

## 4. Модель определений

Законодательство состоит из **определений**, которые лежат в **актах**. Определения создают понятия, из которых мир строит свои вещи. Например, определение органа «Министерство юстиции» в конституции позволяет миру создать здание этого органа и его сотрудников.

### 4.1 Общая основа определения \[По умолчанию\]

У любого определения есть: идентификатор (уникальный во всей системе), название, акт-владелец и список зависимостей (на какие другие определения оно ссылается). Реестр и граф зависимостей работают с этой общей основой и не знают конкретных видов. Новые виды определений (из модов) добавляются без изменения реестра.

Не нужно перегружать определения лишними полями. Поле «описание» **убрано**, потому что его неоткуда автоматически получить. **\[Принято\]**

### 4.2 Корневые категории субъектов \[Принято\]

На уровне базы задаются два абстрактных определения:

- **Физическое лицо**: отдельный человек.
- **Организация**: объединение субъектов. Формулировка «объединение людей» уже, чем нужно, потому что организации могут объединять и другие организации (ассоциации, союзы).

Это природа субъекта, её нельзя отозвать и она не меняется. Всё остальное (юридическое лицо, НКО, партия, СМИ, депутат, бездомный) это статусы, которые определяют акты.

Замечание: организация не обязана быть юридическим лицом. Незарегистрированные объединения существуют и в реальности, что даёт игровую механику запрета организаций без их уничтожения.

### 4.3 Статус \[Принято\]

Статус это термин, который назначается субъекту решением органа и записывается в реестре. Примеры: иностранный агент, депутат, бездомный, психически больной, юридическое лицо, НКО, политическая партия.

Свойства:

- **Область применимости.** Каждый статус указывает, к кому он применим: к физическим лицам, к организациям или к обоим корням. Иностранный агент применим к лицам и организациям, депутат только к физическим лицам. Валидатор отвергает назначение статуса не тому субъекту.
- **Один родитель.** Статусы образуют дерево: партия вид общественного объединения, оно вид НКО, оно вид юридического лица. Несколько родителей не нужны, потому что совмещение выражается набором статусов (иностранная НКО это два независимых статуса).
- **Выведение по цепочке.** В реестре хранится только та запись, которую выдал орган («партия»). Вышестоящие статусы выводятся из определений и отдельных записей не имеют.
- **Наследование области применимости.** Статус не может быть применим к более широкому кругу, чем его родитель. Циклы запрещены.
- **Права не хранятся в статусе.** Статус служит условием в нормах: норма читает статус и возвращает вердикт. Один и тот же статус может как расширять, так и ограничивать возможности.

Следствие выведения: у выведенного статуса нет собственной записи «кто выдал» и «когда». Для таких вопросов используется запись исходного статуса. **\[Открыто\]**: если когда-нибудь разные органы должны выдавать разные звенья одной цепочки, схему придётся расширять. Открыт и вопрос частичного снятия: если партия лишена регистрации, а организация остаётся как незарегистрированное объединение, это придётся описывать отдельной выдачей статуса.

### 4.4 Состояние \[Принято\]

Состояние это термин, который не записывается в реестр, а **наблюдается** в момент проверки: алкогольное опьянение, нахождение в толпе. Источник данных отличается от статуса (статус выдан и записан, состояние измерено), и подделка работает по-разному. В снимке субъекта это отдельное поле (раздел 5).

### 4.5 Алиас \[Принято\]

Алиас это именованная обёртка над значением базового типа, которую можно использовать в любых нормах. Пример: «ночное время» как интервал времени суток 00:00 до 06:00, или «радиус точки сбора» как расстояние 20 метров. Алиас не назначается субъекту и не хранится в реестре. Его тип определяет, какие операции с ним допустимы.

### 4.6 Орган \[Принято\]

Орган это определение из двух полей: идентификатор и название. Полномочия органа выражаются нормами, а не полями. Орган существует по факту принятия акта, который его определил, и регистрации у других органов не требует. Мир может породить из определения здание, сотрудников и актора-организацию, ядро об этом не знает.

### 4.7 Санкция \[Принято\]

Санкция это термин с типизированными параметрами, а не фиксированный список ядра. Примеры: штраф (сумма, валюта), заключение под стражу (длительность), присвоение статуса (ссылка на термин-статус). «Санкций не предусмотрено» тоже определение санкции. Подробности в разделе 9.

### 4.8 Норма \[Принято\]

Норма это один закон. Из неё строится AST, и она выполняется интерпретатором. У неё есть имя, типизированная сигнатура (параметры, которые обязан передать наблюдатель), тело (выражение) и результат: вердикт или «не применима». Отдельного определения «вид ситуации» нет, сигнатура нормы сама является контрактом для мира.

Норма может запрещать действие («выход из дома») или состояние («нахождение в толпе»). Для ядра это одно и то же, различие только в названии ситуации.

### 4.9 Акт \[Принято\]

Акт это контейнер для определений и норм (конституция, кодекс, указ). Правила видимости описаны в разделе 10.

### 4.10 Виды определений, отложенные на потом

Действия (деяния), документы и решения (лицензия, приговор), вещи и объекты права, пространственные термины (место, зона). Для текущих примеров они не нужны. **\[Открыто\]**: нужен ли отдельный пользовательский тип-запись (структура из полей), или хватит статусов с атрибутами.

## 5. Субъекты, реестры и снимок

### 5.1 Актор

Актор это внутренняя базовая единица мира: физическое лицо или организация. Это сущность с набором компонентов. Библиотека права актора не видит и от него не зависит: закон работает только со снимком (5.4). Общая маленькая сборка с минимальным контрактом актора нужна миру и другим библиотекам. **\[По умолчанию\]**

**\[Открыто\]**: что именно называется компонентом (ECS в духе Unity DOTS или композиция объектов внутри класса актора). Для библиотеки права это не важно, но важно для общей сборки.

### 5.2 Запись назначения статуса

Статус у субъекта это назначение, а не метка. Это структура данных (не строка) с полями:

- ссылка на термин-статус;
- кто назначил (идентификатор актора);
- когда назначено (момент времени);
- срок действия (может отсутствовать);
- необязательные атрибуты. **\[По умолчанию\]** Список полей можно расширять.

Поля «кто» и «когда» нужны, чтобы работали проверки полномочий: «статус иноагента выдала полиция, а должен был Минюст».

### 5.3 Реестры \[Принято\]

Назначения хранятся не в акторе, а в **реестрах организаций**: розыск ведёт полиция, медицинские статусы ведёт министерство здравоохранения. Это решает проблему «любой прохожий может пробить любого». Реестры принадлежат миру. Библиотека права знает только формат записи.

### 5.4 Снимок субъекта \[Принято\]

Закону передаётся **неизменяемый снимок**, который собирает наблюдатель из того, до чего он имеет доступ. Полицейский видит статусы из реестров полиции, прохожий почти ничего.

Состав снимка:

- идентификатор субъекта;
- поле **назначений** (записи статусов из доступных реестров);
- поле **состояний** (то, что наблюдатель измерил или увидел). Это два отдельных поля.

Свойства:

- У снимка нет методов записи. В пределах одного вычисления любое чтение возвращает одно и то же значение.
- Снимок может содержать ложь: подделку и ошибки закон не обнаруживает.
- Снимок может раздуваться. Как собирать только нужное для конкретной нормы, решаем на этапе проектирования мира. **\[Открыто\]**

### 5.5 Принцип незнания

Статус, которого нет в снимке, для закона не существует. Если норма проверяет статус и не находит его, её условие обычно не выполняется и результат «не применима». Отдельной механики незнания закон не содержит.

### 5.6 Принадлежность к органу \[Принято\]

Закон не знает, сотрудник какого органа читает его, и знать не должен. Принадлежность к органу это обычный статус в снимке, например «сотрудник полиции», который назначил и записал соответствующий реестр. То же верно для должностей и ролей (чиновник, депутат): это статусы, а не особые связи.

Пример: норма «сотруднику полиции запрещено находиться в алкогольном опьянении» получает снимок субъекта со статусом «сотрудник полиции» (из реестра) и состоянием «алкогольное опьянение» (измерено наблюдателем). Норма проверяет оба и возвращает вердикт.

**\[По умолчанию\]** Чтобы проверить полномочия того, кто выдал статус, наблюдатель так же собирает и передаёт снимок выдавшего. Отдельных узлов и связей с органами для этого не нужно.

### 6.2 Таблицы операций («механизм исчисления») \[Принято\]

У каждого типа есть набор допустимых операций: сравнение, арифметика, пересечение интервалов и т. д. Допустимость определяет тип операнда, а не узел AST. Примеры: момент минус момент даёт длительность; момент плюс длительность даёт момент; интервал времени суток содержит время суток; сумма плюс сумма в одной валюте.

### 6.3 Расширяемость \[Принято\]

Моды и будущие версии могут добавлять типы вместе с таблицей их операций и встроенными чистыми функциями. Новые виды узлов AST добавлять нельзя. Список базовых типов должен допускать расширение с самого начала.

### 6.4 Время

Игровые часы поступают в закон аргументом. Закон никогда не читает системное время. Календарь, часовой пояс и длительность игровых суток **\[Открыто\]**.

| Категория | Узлы |
| --- | --- |
| Значения | Литерал(тип, значение); СсылкаНаОпределение(id); Параметр(имя); Локальная(имя); Объявить(имя, выражение); Присвоить(имя, выражение) |
| Вычисления | Операция(id операции, операнды); И, Или (ленивые); Не; ВстроеннаяФункция(id, аргументы) |
| Управление | Блок; Если(условие, то, иначе); Пока(условие, тело); ДляКаждого(список, имя, тело); Вызов(id, аргументы); Вернуть(выражение); Прервать; Продолжить |
| Данные | Поле(запись, имя); ИмеетСтатус(снимок, статус); ЗаписиСтатуса(снимок, статус); Состояние(снимок, состояние); запросы над списком: Количество, Существует, Все, Отфильтровать |
| Результат | Вердикт(модальность, список санкций, причина); НеПрименима |

### 7.1 Особенности

- Присвоение допустимо только для локальных переменных. Состояние мира закон изменить не может.
- Вернуть, Прервать и Продолжить закладываются сразу **\[Принято\]**, потому что добавлять их позже тяжело. У них тип «Никогда», поэтому конструкция вроде «Если(..., Вернуть(...), ...)» проходит проверку типов.
- Рекурсия допускается, от зацикливания защищает gas.
- ИмеетСтатус учитывает цепочку «вид» (4.3): проверяются запись самого статуса и записи статусов, чьи цепочки ведут к нему.
- Запросы над списком выразимы через ДляКаждого, но вынесены отдельно ради редактора блоков и простоты оценки цены.

**\[Открыто\]**: что именно можно вызывать узлом Вызов. Термины не являются функциями (4.3, 4.5), поэтому нужно решить, есть ли в языке пользовательские функции или одни нормы вызывают другие.

## 8. Выполнение

### 8.1 Запрос

Мир находит нужную норму сам, собирает аргументы (снимки, момент времени, списки) в соответствии с её сигнатурой и вызывает интерпретатор. Закон выполняется один раз за запрос и ничего не помнит.

### 8.2 Результаты вычисления

| Результат | Смысл | Кто производит |
| --- | --- | --- |
| Вердикт | модальность, список санкций, ссылка на норму, израсходованный gas | интерпретатор |
| Не применима | норма найдена и выполнена, но её условие не сработало | интерпретатор |
| Прервана | закончился gas, закон слишком сложен, чтобы его применить | интерпретатор |
| Ошибка вызова | мир нарушил контракт (неверный тип аргумента, нет параметра) | интерпретатор |
| Закон молчит | нормы для ситуации нет | только мир |

«Закон молчит» лежит в общем словаре результатов, но интерпретатор его никогда не возвращает, потому что нормы ищет мир. Как мир должен реагировать на «Ошибку вызова» (отказ или иное), решим при проектировании интерпретатора **\[Открыто\]**.

### 8.3 Gas \[Принято\]

- Каждый вычисленный узел стоит единицу. Операции над списками стоят по единице за элемент. Вызов определения стоит дополнительно единицу. Таблица цен настраиваема без изменения AST **\[По умолчанию\]**.
- Измеряется фактическая стоимость выполнения. Статическая оценка верхней границы возможна только для частей без циклов и рекурсии и откладывается.
- Стоимость закона становится игровой механикой: чем запутаннее закон, тем он дороже в применении, и запутанность создаёт почву для коррупции.

### 8.4 Способ выполнения

Интерпретатор обходит дерево рекурсивно (tree-walking). У него есть окружение (таблица «имя → значение» с новой областью на каждый вызов) и счётчик gas. Каждый узел возвращает результат с признаком: обычное значение, возврат, прерывание, продолжение. Вызывающие узлы пропускают признак наверх. Исключения для управления потоком не используются **\[Принято\]**.

### 8.5 Валидатор (проверка при сборке)

- совместимость типов, включая тип «Никогда»;
- все пути нормы возвращают вердикт или «не применима» нужного типа;
- доступность ссылок по правилам видимости актов (раздел 10);
- отсутствие циклов в цепочках статусов и зависимостях между актами;
- область применимости статусов и соответствие аргументов сигнатурам.

Валидатор собирает **все ошибки за один проход**, а не останавливается на первой.

## 9. Вердикт и санкции

### 9.1 Вердикт

Вердикт это значение, которое возвращает норма. Он ничего не исполняет, а только называет последствия. Исполняет их мир.

- **Модальность** **\[Принято\]**: Разрешено, Запрещено, Обязательно. Модальности «Молчит» внутри вердикта нет, потому что «закон молчит» производит только мир (8.2).
- **Список санкций** **\[Принято\]**: составная санкция это список санкций.
- **Ссылка на норму**, сработавшую при вычислении. **\[По умолчанию\]**
- **Причина** (текст или ссылка). **\[По умолчанию\]**

### 9.2 Санкции

Санкция это термин с типизированными параметрами (4.7):

| Санкция | Параметры |
| --- | --- |
| Штраф | сумма и валюта |
| Заключение под стражу | длительность |
| Присвоение статуса | ссылка на термин-статус |
| Санкций не предусмотрено | нет |

Перечень расширяем: игрок вводит новые санкции в актах. «Санкций не предусмотрено» это отдельное определение, а не пустой список. Оно позволяет выразить «запрещено, но наказания нет» и отличить это от забытой санкции.

**\[Открыто\]**: как записывается вердикт «Разрешено» (санкций по смыслу нет): пустым списком или особым определением. Порядок и приоритет санкций внутри списка. Денежные единицы: валюта как термин принята, остальное не проработано.

## 10. Акты и реестр определений

### 10.1 Правила видимости \[Принято\]

- Акты образуют дерево с корнем в конституции. Один вышестоящий акт у каждого нижестоящего **\[По умолчанию\]**.
- Нижестоящий акт видит определения вышестоящих и может использовать их термины и названия законов. Обратное запрещено: конституция не может ссылаться на кодекс.
- **Переопределения нет.** Видимое определение только читается и не заменяется.
- **Соседние акты** друг друга не видят. Общие понятия поднимаются в общий вышестоящий акт.
- Затенение запрещено: нижестоящий акт не может объявить имя, которое уже видно ему сверху. **\[По умолчанию\]**
- Технические идентификаторы определений уникальны во всей системе, чтобы мир мог надёжно сослаться на любое определение. **\[По умолчанию\]**
- Видимость сверху вниз исключает циклические зависимости между актами по построению.

### 10.2 Реестр определений

Реестр хранит акты и определения и ведёт **граф зависимостей**: кто на кого ссылается. При сборке акта он проверяет, что каждая ссылка указывает на доступное определение.

### 10.3 Запрет изменения используемого \[Принято как упрощение\]

На первом этапе нельзя изменить сигнатуру или удалить определение, на которое есть ссылки. Это временная политика, а не закон природы. Она должна быть отдельным заменяемым правилом реестра, а не вшитой в каждую операцию. Если запрет снять, появятся «висячие» нормы, ссылки которых потеряны. Для них потребуется состояние «недействительна» и способ переоценки после правки. **\[Открыто\]**

### 10.4 Что решает мир

Мир сам выбирает, какой акт применить, и разрешает коллизии, в том числе внутри одного акта. Иерархия по приоритету это условность, которую мир соблюдает или нарушает. Например, полицейский оперирует терминами уголовного кодекса, защитник терминами конституции.

## 11. Ошибки

Ошибки это неизменяемые значения с иерархией видов, как наследуемые типы в C#. Список видов растёт по ходу разработки. Исключения не используются **\[Принято\]**.

У каждой ошибки есть:

- код вида из иерархии;
- понятный человеку текст (например, «термин "точка сбора" недоступен в этом акте»);
- место: путь к узлу в дереве закона, чтобы редактор подсветил нужный блок.

| Категория | Когда возникает | Примеры |
| --- | --- | --- |
| Ошибки сборки | валидатор при сборке закона | несовместимые типы, невидимое определение, цикл, путь без возврата |
| Ошибки вызова | мир нарушил контракт при вызове | неверный тип аргумента, пропущен параметр |
| Игровые исходы | не ошибки, нормальные результаты | «не применима», «прервана» (закончился gas) |

Игровые исходы нельзя смешивать с ошибками, иначе сложный закон придётся обрабатывать как сбой.

## 12. Сериализация

- Законы (деревья AST), акты и определения сериализуются в JSON **\[Принято\]**.
- Ссылки между определениями идут по идентификаторам, а не по названиям, чтобы переименование ничего не ломало. **\[По умолчанию\]**
- Выбор JSON-библиотеки (System.Text.Json или Newtonsoft.Json) не сделан. **\[Открыто\]**
- Версионирование актов и обратная сила законов отложены. **\[Принято\]**

## 13. Примеры

Ниже два закона из обсуждения, разложенные в дерево. Это иллюстрация модели, а не окончательный формат.

### 13.1 Иностранные агенты на улице ночью

Закон: иноагентам запрещено находиться на улице с 22:00 до 08:00.

Определения:

- Статус «Иностранный агент» (применим к физическим лицам и организациям).
- Алиас «Ночное ограничение» = интервал времени суток 22:00–08:00.

Норма: ИноагентНаУлице(субъект: Снимок, сейчас: Момент), результат: Вердикт или «не применима».

```
Если
├── условие: И
│   ├── ИмеетСтатус(субъект, ИностранныйАгент)
│   └── Содержит(НочноеОграничение, ВремяСуток(сейчас))
├── то:    Вердикт(Запрещено, [санкция])
└── иначе: НеПрименима
```

Примечания:

- Интервал, переходящий через полночь, обрабатывает тип «интервал времени суток», а не закон.
- Что лицо находится на улице, закон не проверяет: наблюдатель запрашивает норму только в таких случаях. Нужен ли для этого отдельный термин-состояние, не решено.
- Норма «статус иноагента выдаёт только Минюст» это отдельная норма о полномочиях. Принадлежность к органу выражается обычным статусом в снимке проверяющего (5.6).

### 13.2 Точка сбора

Закон: нельзя собираться больше чем по 10 человек в одной точке сбора.

Определения:

- Алиас «Радиус точки сбора» = расстояние 20 метров.

Норма: Собрание(расстояния: Список<Расстояние>), результат: Вердикт или «не применима».

```
Если
├── условие: Больше(
│     Количество(расстояния, d, МеньшеИлиРавно(d, РадиусТочкиСбора)),
│     9)
├── то:    Вердикт(Запрещено, [санкция])
└── иначе: НеПрименима
```

Примечания:

- Наблюдатель сам считает расстояния до окружающих. Закон не знает положений. Это упрощение действует, пока тип «Положение» отложен.
- «Больше 10 человек»: считать ли самого актора, **\[Открыто\]**. В примере принято «актор плюс более 9 других».
- Радиус можно менять, а сигнатуру алиаса нельзя, пока его используют нормы (10.3).

## 14. Открытые вопросы

1. Что такое компонент актора и нужна ли общая сборка с контрактом актора (5.1).
2. Пользовательские типы-записи (документы, решения, лицензии) как отдельный вид определения или статусы с атрибутами (4.10).
3. Область применимости статусов: как термин указывает, к кому он применим, и как это проверяет валидатор (4.3).
4. Выведенные статусы: кто и когда выдал, частичное снятие статусов (4.3).
5. Действия, документы, вещи, пространственные термины, тип «Положение» (4.10, 6.1).
6. Узел «Вызов»: что можно вызывать, раз термины не функции (7.1).
7. Обработка «Ошибки вызова» миром (8.2).
8. Таблица цен gas (8.3).
9. Календарь, часовой пояс и длительность игровых суток (6.4).
10. Прочие величины СИ, денежные операции и курсы (6.1, 9.2).
11. Запись вердикта «Разрешено», порядок санкций в списке (9.2).
12. Состояние «недействительна» для норм с потерянными ссылками (10.3).
13. Снимок: способы не раздувать, потенциальная многопоточность (5.4).
14. JSON-библиотека (12).
15. Версионирование актов и обратная сила законов (12).
16. Идея, не подтверждённая автором: рендер дерева закона в читаемый текст для игрока.

## 15. План разработки и правила работы

### 15.1 Порядок модулей

1. Система значений и типов (базовые типы, таблицы операций).
2. Узлы AST.
3. Валидатор типов и ссылок.
4. Интерпретатор с gas.
5. Реестр определений и граф зависимостей.
6. Сериализация в JSON.

### 15.2 Правила работы

- Общение и код на русском языке. В коде нет комментариев и блоков Summary.
- Код не пишется, пока автор явно не попросит.
- За одну генерацию создаётся один файл (или один логический модуль), чтобы разбирать неточности по ходу.
- Присланный код анализируется: слабые стороны, лишние данные, неверное поведение.
- Если данных не хватает, об этом сообщается без домыслов.

## 16. Глоссарий

| Термин | Значение |
| --- | --- |
| Акт | Контейнер определений и норм (конституция, кодекс, указ). |
| Алиас | Именованная обёртка над значением базового типа. |
| AST | Абстрактное синтаксическое дерево закона. |
| Gas | Счётчик шагов вычисления, ограничивающий его и измеряющий цену закона. |
| Наблюдатель | Актор, который собирает данные и вызывает закон. |
| Назначение | Запись статуса у субъекта в реестре: термин, кто назначил, когда, срок. |
| Норма | Один закон, чистая функция, возвращающая вердикт или «не применима». |
| Определение | Любое понятие, объявленное в акте: статус, состояние, алиас, орган, санкция. |
| Орган | Определение из идентификатора и названия, из которого мир порождает здания и сотрудников. |
| Снимок | Неизменяемое представление субъекта для закона. |
| Состояние | Наблюдаемое и не записываемое свойство субъекта. |
| Статус | Назначаемое органом и записываемое в реестре свойство субъекта. |
| Субъект | Физическое лицо или организация. |
